# Rebuilding `data/features`

The `data/features` directory contains per-mask embeddings generated by running frozen encoders over published masks. 
No encoders are trained and no masks are proposed during this stage.

These scripts are strictly for rebuilding the feature archive from scratch, verifying cached files, or extending the pipeline to custom datasets. 
They are **not required** to reproduce the benchmark numbers reported in the paper if you are using the pre-packaged archive.

### Feature Extraction Scripts

The scripts below generate the feature archive and are named according to their outputs:

| Writer Script | Output Target | Encoder & Source Masks |
| :--- | :--- | :--- |
| `oy_uni3d.py` | `oyuni_s{0,1}.npz` | Uni3D-giant over Open-YOLO3D's ScanNet200 masks |
| `oy_eva.py` | `evaoy_s{0..3}.npz` | EVA02-E-14-plus over crops of the same masks |
| `oy_clipL.py` | `s2doy_s{0..3}.npz` | CLIP ViT-L-14-336 over the same crops |
| `oy_yolo_votes.py` | `yolovotes/`, `yolovotes_replica/` | Open-YOLO3D's YOLO-World labeling (reproduced in place) |
| `scannetpp_votes.py` | `yolovotes_scannetpp/` | Open-YOLO3D's YOLO-World labeling applied to ScanNet++ |
| `o3d_released_uni3d.py` | `o3drel_uni/` | Uni3D-giant over Open3DIS's released masks |
| `replica_dump.py` | `replica/` | Image towers and Uni3D on Replica, plus 48-class text anchors |
| `openshape.py` | `openshape_oy_s0.npz` | OpenShape over ScanNet200 masks (Table III shape encoder) |
| `text_anchors.py` | `bigg_text_200.npy`, `replica/bigg_text_48.npy` | OpenShape's class anchors (OpenCLIP ViT-bigG space) |

**Note:** EVA02-E and CLIP ViT-L text anchors are not rebuilt via these scripts; they are committed permanently under `assets/fusion/`.

## Execution and Environments

Most feature extraction scripts run in the default repository environment and require one GPU each. 
The ScanNet200 writers are sharded by scene and can be distributed across multiple devices. 

**Memory Warning:** The EVA02-E model (4B parameters) requires approximately 28 GB of host memory during loading. Stagger the initialization of these extraction passes rather than launching them concurrently.

```sh
# Standard repository environment
for K in 0 1;     do python scripts/extract/oy_uni3d.py  --dump data/features/oyuni_s$K.npz \
                         --shard $K --num_shards 2 --device cuda:$K; done
for K in 0 1 2 3; do python scripts/extract/oy_eva.py    --dump data/features/evaoy_s$K.npz \
                         --shard $K --num_shards 4 --device cuda:$K; done
for K in 0 1 2 3; do python scripts/extract/oy_clipL.py  --dump data/features/s2doy_s$K.npz \
                         --shard $K --num_shards 4 --device cuda:$K; done

python scripts/extract/o3d_released_uni3d.py
python scripts/extract/replica_dump.py --stage clipL
python scripts/extract/replica_dump.py --stage eva
python scripts/extract/text_anchors.py --dataset scannet200
python scripts/extract/openshape.py
```

The vote generation scripts rely on the YOLO-World and detectron2 stack, meaning they **must be executed within the Open-YOLO3D environment**. 
Both scripts are resumable at the scene level.

```sh
# Open-YOLO3D environment
python scripts/extract/oy_yolo_votes.py --dataset scannet200
python scripts/extract/oy_yolo_votes.py --dataset replica
python scripts/extract/scannetpp_votes.py
```

## Additional Inputs

In addition to the checkpoints and masks listed in `data/DATASETS.md`, feature extraction requires the raw 3D scans. 
These are not required for standard evaluation.

| Variable | Default Path | Description |
| :--- | :--- | :--- |
| `SCANNET200_ROOT` | `data/scannet200` | Preprocessed Mask3D-format meshes (`{train,val}/<scene>.ply`). |
| `SCANNET_V2_ROOT` | `data/scannet_v2` | Raw ScanNet export (`scans/<scene>/`) containing color, depth, poses, and intrinsics. |

**Mesh Alignment Note:** The preprocessed mesh is axis-aligned and serves as the index for the released proposals. 
The raw mesh remains in the original camera pose frame and is required for accurate 2D mask projection. 
Both meshes share the identical vertex order, allowing proposals to be mapped seamlessly between them.
